# Формы сайта

Что происходит, когда человек заполняет форму «Остались вопросы?» на
anastasia-samadhi.club:

1. Данные проверяются, спам-боты отсекаются
2. **Строка пишется в Google-таблицу** — это делается первым и всегда, чтобы
   обращение не потерялось из-за сбоя на следующем шаге
3. Модель решает, относится ли вопрос к работе Анастасии
4. Если относится — пишет ответ её голосом, и письмо уходит **с адреса
   `hello@anastasia-samadhi.club`**, а ответы человека приходят на
   `hello@metasouls.co`
5. Анастасии в любом случае приходит уведомление с копией того, что ушло от её
   имени

Форма подписки на рассылку короче: адрес попадает в ту же таблицу, приходит
уведомление.

Всё после записи в таблицу обёрнуто в перехват ошибок. Отказ модели или почты
стоит автоответа, но никогда — записи и уведомления; в этом случае в
уведомлении написано, что ответить нужно самой, и почему.

## Почему отдельный сервис

Сайт статический и лежит на GitHub Pages. Всё, что попадает в страницу, может
прочитать любой посетитель — включая ключи. Поэтому ключи живут в Cloudflare
Worker, а сайт знает только его адрес (`API_BASE` в `src/api.ts`).

## Откуда берётся содержимое писем

Из `src/content.ts` — того же файла, из которого рисуется сайт: цены, частые
вопросы, описания форматов, отзывы, ссылки. Поменяли цену на сайте — письма
начинают называть новую. Двух версий одной цифры быть не может.

Модели разрешено называть цены, но **только дословно**: без округлений, без
пересчёта в другую валюту, без деления на количество сессий. Даты, сроки старта
и наличие мест запрещены совсем — они меняются, а устаревшее обещание в письме
хуже, чем его отсутствие.

## Что где лежит

```
api/src/index.ts      маршруты и порядок действий
api/src/knowledge.ts  справка для модели, собирается из src/content.ts
api/src/openai.ts     инструкция модели и разбор ответа
api/src/resend.ts     отправка письма
api/src/sheet.ts      запись строки в таблицу
api/src/check.ts      самодиагностика внешних сервисов
api/apps-script/      скрипт, который вставляется в Google-таблицу
```

## Настройки

Четыре секрета, задаются в Cloudflare (**Settings → Variables and Secrets**,
тип **Secret**):

| Имя | Что это |
|---|---|
| `OPENAI_API_KEY` | ключ с platform.openai.com |
| `RESEND_API_KEY` | ключ с resend.com |
| `SHEET_ENDPOINT` | адрес развёрнутого Apps Script |
| `SHEET_SECRET` | пароль, совпадающий с `SECRET` внутри скрипта |

Остальное имеет значения по умолчанию прямо в коде и задаётся только если нужно
поменять: `FROM_EMAIL`, `REPLY_TO`, `NOTIFY_TO`, `ALLOWED_ORIGINS`, `SITE_URL`,
`OPENAI_MODEL`.

Секреты очищаются от пробелов и переносов строк — при вставке в поле браузера
они цепляются очень легко, а сервис потом отвергает ключ, который на экране
выглядит правильным.

## Проверка

Открыть адрес воркера в браузере:

- **`/`** — версия, действующие настройки и **длина** каждого секрета. Длина, а
  не «есть/нет»: обрезанную вставку видно сразу по несовпадающему числу
- **`/check`** — спрашивает у OpenAI, какие модели доступны ключу, и у Resend,
  подтверждён ли домен. Обе проверки бесплатны и ничего не отправляют

Если модели `gpt-4o-mini` не окажется в списке — добавить переменную
`OPENAI_MODEL` с любым именем из того же списка. Код трогать не нужно.

## Разработка

```bash
node api/test.mjs      # 58 проверок против поддельных OpenAI, Resend и Google
node api/bundle.mjs    # собрать один файл для вставки в редактор Cloudflare
```

Тесты не требуют ключей и не ходят в сеть: все три внешних сервиса подменяются.
Покрыты обычный путь, вопрос не по теме, пустой ответ модели, отказ каждого из
трёх сервисов по отдельности, проверки ввода, ловушка для спам-ботов и запрос с
чужого сайта.

Для тех, кому привычен терминал, вместо вставки в редактор работает
`npx wrangler deploy` — настройки лежат в `wrangler.toml`.
